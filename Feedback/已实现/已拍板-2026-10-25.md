## IMPR-007：`deploy.py` 要不要也同步 `.workbuddy/skills/unity-cmd/`

**用户批注（会话原话）**：

> mcp 侧如果需要更新，那要同步更新

→ 判定为「做」，并采用原提议的口径：**默认开、`--no-skill` 可关、目标更晚时不覆盖**。

### 怎么改的

`Tools/deploy.py`：

- 新增常量 `BRIDGE_ROOT` / `SKILL_DIR_REL` / `SKILL_FILES`，映射关系写死但只有三行：
  `McpBridge/SKILL.md → <skill_root>/.workbuddy/skills/unity-cmd/SKILL.md`，
  `send.py → scripts/send.py`，`unity_mcp_server.py → scripts/unity_mcp_server.py`。
- `build_skill_plan()` / `apply_skill_plan()` / `report_skill()`，
  与 Assets 那套 `build_plan()` / `apply_plan()` 同构，复用 `norm()` / `to_eol()` / `write_atomic()`。
- **冲突守卫**：目标那份内容不同、且 mtime 比仓库源更晚 → 不覆盖，报
  `! <文件> 目标那边更晚（…> …），不覆盖；--force-skill 才硬写`。
  理由：工程里那份被人改过的话，覆盖等于吃掉他的改动。
- 部署后闭环重算一次，不一致算 `failures`；仅冲突不算失败（只在报告里点出来，退出码仍 0）。
- `--check` / `--list` / `--dry-run` 都会报告 MCP 桥状态，不写盘。

`Tools/deploy_targets.json`：新增可选字段 `skill_root`，默认等于工程根。
**CivelRev 必须单列**：它的 MCP 条目指向 `CivelRev/Demo/.workbuddy/skills/unity-cmd/scripts/unity_mcp_server.py`
（工作区根），而工程根是 `CivelRev/Demo/CivilizationRevival`——不单列就会往一个没人读的位置写第二份。
