## IMPR-010：Phase 2 运行时闭环（`wait.*` / `runtime.screenshot` / 跨帧执行器）

**用户批注**：

> 可以

我的原提议是两档：完整的服务端跨帧执行器（风险最高的一块），或**只做客户端侧等待**（服务端零改动）。
批注只有一个"可以"，按我倾向执行 —— **只做客户端侧等待**，服务端一行没动。

**执行结果**：`send.py` 新增 `seq` 子命令（提交 `f4b41d3`）：

- 步骤文件 `{"steps":[{"label","commands","waitAfterMs","stopOnError","waitBusy"}]}`，
  普通指令文件也可直接当单步脚本用。
- 一步一个 HTTP 请求，步间由客户端 `sleep`；`--request-id X` 按步派生 `X-1`/`X-2`，
  重跑整份脚本不会把已成功的步骤再执行一遍。
- 退出码：`0` 全成功、`1` 某步失败或有步未执行、`3` 协议层被拒、`4` 等空闲超时、`2` 步骤文件不合法。
- `SKILL.md` 新增「顺序执行（客户端侧等待）」一节，并改写「三条硬边界」第 1 条指向它，
  同时点明**服务端 `batch` 解决不了这件事**（它在一个 tick 内跑完，中途不让帧推进）。

| 验证 | 结果 |
| --- | --- |
| `py_compile` | ✅ |
| 三步正常路径（含 700ms 等待） | ✅ 退出码 0，内部耗时 0.8 s（含等待），说明 sleep 真的生效 |
| `stopOnError` 默认 true | ✅ 第 2 步坏 ID 后停下，后 1 步未执行，退出码 1 |
| `stopOnError:false` | ✅ 失败后继续执行下一步 |
| 普通指令文件当单步 | ✅ |
| 坏 JSON / 空 `steps` | ✅ 退出码 2，报错指出文件名 |
| `--dry-run` | ✅ 每步「校验通过（dry-run，N 条未执行）」 |
| 部署后那份脚本实跑 | ✅ 三个工程副本与仓库逐字节一致（忽略行尾） |

**没做的**：服务端跨帧执行器、`runtime.screenshot`、断言原语、`runtime.invoke`。
理由不变：要动 `CommandRunner` 的同步语义与 120 秒超时，是本系统最脆的一块。

**顺带发现的**（已单独立项 IMPR-014，待拍板）：端点发现每次固定花约 18 秒 —— 信息文件那条
