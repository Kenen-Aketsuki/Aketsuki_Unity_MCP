## 症状

两个编辑器窗口在窗口被压矮、内容超出可视高度时，无法滚动到被裁掉的区域：

- **指令系统窗口（`CommandToolsWindow`，即「指令系统」面板）**：`OnGUI()` 直接顺序绘制「执行 / 设置 / HTTP / 运行时 / 敏感操作确认 / 指令列表 / 日志」七大区块，**没有用 `BeginScrollView` 包住整体**。窗口高度不够时，靠下的区块（已注册指令列表、运行日志）被裁掉且滚不到；虽然指令列表区（`GUILayout.Height(150)`）和日志区（`GUILayout.Height(160)`）各自有内部滚动，但整体布局不可滚。
- **ADB 调试台（`AdbDebugWindow`）**：`OnGUI()` 已用 `EditorGUILayout.BeginScrollView(_scroll)` 包住 `DrawCaptureSection + DrawHelp`，源码层面整体已经可滚。需确认部署到目标工程的版本同样可滚、以及在「设备列表很长 / 多条不可用设备 HelpBox / 连接报错」等撑高场景下实际能滚到底。若你仍看到不可滚，可能是目标工程部署的是旧版，或存在别的裁切点。

## 复现

1. 打开「指令系统」窗口，把窗口高度拖到很小（低于各区块展开后的总高）。
2. 观察：靠下的「已注册指令」「运行日志」被裁切，窗口没有滚动条，滚不到。
3. 同样把「ADB 调试台」压矮，确认整体是否能滚动到底。

期望：窗口任意高度下都有纵向滚动条，能滚到每一个区块、每一行内容。
实际（指令系统窗口）：没有整体滚动条，下方内容永久不可见。

## 待拍板

| | 做好处 | 代价 |
| --- | --- | --- |
| 做 | 小窗口下所有设置/日志都看得全、用得上；不再有"明明有功能却滚不到"的盲区 | 改动小（MCP 窗口加一层整体滚动），风险低 |
| 不做 | 零改动 | 窗口一压矮就丢功能，逼用户把窗口拉很高 |

**指令系统窗口（确定要做）**

| 方案 | 说明 | 代价 |
| --- | --- | --- |
| A. 整体包一层 `BeginScrollView`（推荐） | 在 `OnGUI()` 开头 `BeginScrollView(_windowScroll)`、结尾 `EndScrollView()`；保留现有的「指令列表 150px / 日志 160px」两个内部滚动区 | 嵌套滚动在 IMGUI 里可用；改动小、风险低 |
| B. 去掉内部滚动、只留整体滚动 | 把指令列表/日志的内部固定高度滚动去掉，全交给外层 | 长日志/长指令列表会无限制撑高外层，失去"这两个区固定高度"的意图，不推荐 |

**我的倾向**：方案 A。两块内部滚动区本来就是刻意限高的，整体再加一层滚动只是补上"窗口整体可滚"这最后一块。

**ADB 调试台（先确认再决定）**

- 源码已整体可滚，大概率是已满足需求，可能无需改动。
- 若你在目标工程实测仍不可滚：先确认部署版本是否含本次的 scroll 包裹（2026-10-29 包化后刚部署）；若已含仍不可滚，再排查是不是 `minSize(430,480)` 把窗口顶得够大、普通使用碰不到溢出，还是别的裁切点。
- 备选：无需额外改动；或若你希望 ADB 也统一成"外层滚动 + 内部固定区"的写法，可顺手对齐（目前 ADB 没有内部固定高度区，整体滚已够用）。
